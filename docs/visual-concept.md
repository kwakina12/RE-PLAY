# RE:PLAY — 소비 리플레이

서비스명은 **다시씀**, RE:PLAY는 비주얼 컨셉 이름입니다. “쓴 돈은 지나가도, 내 선택은 남으니까.” 핵심 질문은 “같은 돈이면 다시 쓸래?”, 화면 질문 후보는 “이 소비, 다시 선택할까요?”입니다.

소비를 돌아보고 같은 선택을 반복할지, 바꿀지, 보류할지 선택합니다. 중심 모티프는 **되돌아오는 선**입니다.

| 저장 verdict | 사용자 표시 | 프레젠테이션 motif | 의미 |
|---|---|---|---|
| repeat | 다시 쓸래 | loop | 다시 연결되는 궤적 |
| change | 다음엔 바꿀래 | redirect | 방향이 갈라지는 선 |
| unsure | 아직 모르겠어 | pause | 간격을 두고 멈춘 선 |

src/features/records/constants.ts의 VERDICTS가 단일 매핑입니다. motif는 DB에 저장하지 않습니다. change는 실패·삭제·빨간 X가 아닙니다. unsure는 저장 가능한 완전한 판단이며 초안/예약 작업이 아닙니다. 이유·다음 기준이 없는 unsure 카드도 정상입니다.

기록 하나를 저장한 직후부터 선택의 가치가 보여야 합니다. 누적 개수, 연속 기록, 보상 해금 조건을 두지 않습니다. 음악·영상 서비스가 아니므로 오디오, 플레이리스트, 스트리밍, 재생 시간, 앨범 커버를 추가하지 않습니다. loop는 반복 결제, pause는 구독 일시정지가 아닙니다.

카드 정보 순서: **소비 이름 → 판단 → 이유 → 선택적 다음 소비 기준 → 금액·카테고리·기록일**. 금액은 선택이며 큰 지출 수치가 중심이 아닙니다. 금액 null은 생략하고 0은 0원으로 구분합니다. createdAt은 구매일이 아니라 기록일입니다.

Figma 후보: background #F5F5F0, text #202320, repeat #D9F66F, change #A9B9F5, unsure #DFE2DA. 넓은 여백·중간 라운드·얇은 선·굵은 한글 질문을 검토합니다. 확정 테마나 대비 검증 완료 상태가 아닙니다. 판단은 이름과 기호를 함께 제공해 색에만 의존하지 않습니다. 현재 CSS는 중립 연결 확인용입니다.

브랜드 색·폰트·로고·실제 SVG·모티프 형태·카드·고해상도 UI는 Figma에서 확정합니다. 저장 성공 후 선이 완성되는 짧은 모션은 후속 검토 대상입니다. **DB 커밋 전 성공 표현 금지**, 완료/다음 행동을 모션이 지연시키지 않으며 prefers-reduced-motion에 대응해야 합니다. 현재 애니메이션 라이브러리와 3D 에셋은 없습니다.
